# 这个插件能把哪些数据传给手机

按「可靠性」分三档：**官方接口**（稳定）、**反射读取**（尽力而为）、**拿不到**。

协议字段的完整定义见 [`协议参考.md`](协议参考.md)。

---

## 一、官方接口（稳定，不会随宿主升级失效）

### 1. 曲目元数据

来源 `PlaybackExtensionPoint.MediaItem`，也是 `state` 里最可靠的部分：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `title` | String | 标题 |
| `artist` | String | 艺术家，多艺术家用 `/` 分割 |
| `album` | String | 专辑 |
| `albumArtist` | String | 专辑艺术家 |
| `path` | String | 文件路径（Windows 风格，如 `C:\Music\x.flac`） |

**当前宿主只有这 5 个基础字段**；`id` / `duration` 在 dev21+ 才有（插件已经用上），
其余 `year` / `genre` / `number` / `isFavorite` / `readable` 暂未下发。

### 1.2 封面与完整歌词（插件 1.5 / 协议 v2）

| 数据 | 来源 | 发送方式 |
| --- | --- | --- |
| 内嵌封面 | `library.getCoverById(id)`（需 `LIBRARY_READ`） | 换曲时压成最长边 640 的 JPEG，base64 放进 `trackExtra.cover` |
| 完整歌词时间轴 | `playback.getLyricsLines()` / `onLyricsLinesUpdated` | `trackExtra.lyrics`：`s`/`e` 毫秒 + 原文 + 翻译 |
| 曲目总时长 | `MediaItem.duration`（dev21+） | `state.duration` / `trackExtra.durationMs` |

手机侧**优先用本机曲库**的封面/歌词/时长；只有本机没有时才用 PC 这一份 ——
本地文件通常更清晰、也不用走网络。`trackExtra` 只在换曲和刚配对时发，不跟着每秒的位置广播。

### 2. 播放事件

| 事件 | `state` 里的体现 |
| --- | --- |
| `onStateChanged`（Idle/Buffering/Ready/Ended） | Idle/Ended 时把 `playing` 置 `false` |
| `onIsPlayingChanged` | `playing` |
| `onPositionUpdated`（宿主每秒一次） | `pos`，经 900ms 节流后广播 |
| `onSeekTo` | 触发一次状态刷新 |

## 二、反射读取（尽力而为，失败就降级）

`TrackReflector.kt` 直接读宿主内部字段。**读不到不算错误**，会保留事件推来的值。

| 数据 | 反射目标 | 说明 |
| --- | --- | --- |
| `id` | `MediaItem` 内部字段或 `getId()` | 拿不到是空串。**不要当主键依赖** |
| `playing` | `PiscesMediaMonitor._isPlaying`（或名字含 `isPlaying` 的布尔字段） | 连接建立的瞬间就能给出正确值 |
| `pos` | `PiscesMediaMonitor._progress`（或名字含 `progress` 的字段） | 同上 |
| 曲目本体 | `PlaybackService` 上的 `currentMediaItem` / `selectedMediaItem` / `mediaItem` / `currentItem` / `playingItem` | 按顺序试，命中哪个会报在 `netinfo.trackReflector` |

**为什么播放状态要反射**：宿主当前公开接口没有「随时主动取当前曲目」的方法，
所以「刚连上时宿主已经在播」这种情况拿不到状态，客户端会看到 `playing=false`，
要等下一次事件才纠正。反射读 `_isPlaying` / `_progress` 之后，
**连接建立的瞬间**就能给出正确值。

降级行为：任一环节失败就把 `TrackReflector` 标记为不可用并记下原因，
之后 `current()` 直接返回 null，直到宿主版本号变化才重置。
失败原因会出现在 `netinfo.trackReflector` 和插件日志里，排查时先看这一条。

## 三、网络地址与连接信息

| 数据 | 来源 | 下发给谁 |
| --- | --- | --- |
| 局域网 IPv4 列表 | `NetworkInterface` 枚举（只含 site-local：10/8、172.16/12、192.168/16） | **配对成功后** `netinfo.lan` |
| 全局 IPv6 列表 | `NetworkInterface` 枚举，过滤回环/链路本地/ULA/组播 | **配对成功后** `netinfo.ipv6` |
| 公网 IPv4 | 请求 `api.ipify.org` 等三个服务，缓存 10 分钟 | **配对成功后** `netinfo.public` |
| WebSocket / UDP 端口 | 插件自己的配置 | `netinfo` + **UDP 广播包里也有** |
| 协议版本、插件版本 | `Protocol.VERSION` / `pluginContext.pluginVersion` | `hello`；插件 ID 在 UDP 广播的 `plugin` 里 |
| 反射是否可用 | `TrackReflector` 状态 | `netinfo.trackReflector`（诊断用） |

> 地址列表**只在配对成功后**才通过 WebSocket 下发。UDP 广播里只有身份和端口，
> 没有地址 —— 否则等于把"这台机器开在哪"告诉同网段所有人。

## 四、当前拿不到的

| 数据 | 为什么拿不到 |
| --- | --- |
| **是否已收藏** | 公开接口没有。 |
| **年份 / 曲风 / 音轨号** | 公开接口有字段，但当前版本未接。 |
| **播放列表 / 队列** | 公开接口没有。内部有 `PlaybackQueue`，但读它需要反射更深的内部结构。 |
| **音量 / 播放模式 / 均衡器** | 公开接口完全没有。 |
| **播放历史 / 统计** | 宿主不提供。插件**没有**做记录 —— 代码里除配置文件外没有任何文件读写。 |
| **采样率 / 位深 / 文件是否可读** | 公开接口没有；采样率理论上能从内部 `PiscesInfo` 反射，但不稳定，没有实现。 |

## 五、安全事实（1.4 已修复状态泄露）

设计意图是「配对成功后才推播放状态」，**1.4 起代码已经做到了**：

- `WsServer.broadcast()` 只发给 `Client.authed = true` 的连接（`auth` 校验通过时置位）；
- 连上但没配对的连接只会在 `onOpen` 收到 `authRequired`，之后收不到任何 `state`；
- `MediaState` 用**已配对连接数**做短路：没有已配对设备时连 `state` 的 JSON 都不构造。

同版本还加了两条防护：

- **配对失败限流**：同一 IP 60 秒内失败 5 次 → 断开连接（close 1008）；
- **指令限流**：每连接 1 秒最多 15 条，超出回 `ack(ok=false, err="指令过于频繁，已忽略")` 且不执行。

仍然成立的事实：

| 机制 | 现状 |
| --- | --- |
| UDP 广播内容 | 只有身份和端口；「局域网免配对」默认开启时**额外带配对码**，同网段抓包即可得到 |
| 传输加密 | **没有**。局域网明文 `ws://`；过公网必须自己加 TLS 或隧道 |

| 机制 | 现状 |
| --- | --- |
| 配对码 | 首次运行 `SecureRandom` 生成 `SPW-` + 8 位，写回配置，显示在配置页 |
| 未配对时的指令 | 拒绝，回 `authRequired` |
| 未配对时的 `netinfo` | 拒绝，回 `authRequired` |
| UDP 广播内容 | 只有身份和端口；**「局域网免配对」默认开启时额外带配对码**，同网段抓包即可得到 |
| 传输加密 | **没有**。局域网明文 `ws://`。要过公网必须自己加 TLS 或隧道 |
| 指令限流 | 每连接 1 秒最多 15 条，超出回 `ack(ok=false,"指令过于频繁，已忽略")` 且不执行；另有 `maxClients = 8` |

---

## 六、一句话总结

现在能稳定传的是：**曲目元数据 + 播放状态与进度 + 网络地址 + 封面（JPEG）+
完整歌词时间轴（含翻译）+ 曲目时长**。手机侧优先用本机曲库匹配，
本机没有时才用 PC 那一份。
