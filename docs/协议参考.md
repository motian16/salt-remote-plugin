# 协议参考

面向需要自己实现客户端的人。所有内容都以 `src/main/kotlin/io/github/motian16/spwremote/`
里的代码为准，每条都标了出处。

- 传输：**WebSocket 文本帧承载 JSON**（`ws://<host>:<port>/`，路径任意，服务端不检查）
- 默认端口：WebSocket `52100`（TCP），自动发现 `52101`（UDP）
- 协议版本：`protocol = 1`（`Protocol.kt` 的 `VERSION`）
- 所有消息都有 `t` 字段标识类型
- JSON 键名一律是短名：位置是 **`pos`**（不是 `positionMs`），播放态是 **`playing`**

---

## 一、连接生命周期

```
客户端                          插件
  │  ── TCP 连接 ──────────────► │
  │                              │  WebSocket 握手（101 Switching Protocols）
  │  ◄── authRequired ────────── │  连接一建立就发，且**不推任何播放状态**
  │                              │
  │  ── {"t":"auth","token":…} ► │
  │  ◄── authOk ──────────────── │  配对码正确
  │  ◄── hello ───────────────── │
  │  ◄── state ───────────────── │  配对前会先主动对一次账，所以立刻有真实曲目
  │                              │
  │  ── cmd / ping / netinfo ──► │  之后正常收发
  │  ◄── ack / pong / state ──── │
```

### 鉴权门（`RemotePlugin.kt` 的 `WsListener.onMessage`）

配对之前，除 `auth` 之外的消息**只有 `ping` 被放行**，其余一律回 `authRequired`：

| 未配对时发 | 回复 |
| --- | --- |
| `auth` | `authOk` + `hello` + `state`，或 `authFail` |
| `ping` | `pong`（放行，方便客户端测 RTT） |
| `cmd` / `hello` / `netinfo` / 其他 | `authRequired` |
| 不是 JSON 对象 | `error`（这一条在鉴权门之前，未配对也会回） |

**没有"鉴权超时"机制**：未配对的连接不会被专门踢掉，只会被下面两个通用机制断开。

### 连接管理（`WsServer.kt`）

| 项 | 值 | 说明 |
| --- | --- | --- |
| `maxClients` | 8 | 超出时新连接**直接关闭，不回复任何状态码** |
| `MAX_HTTP_HEADER` | 16 KiB | 握手头超限则握手失败并关连接 |
| `MAX_MESSAGE` | 1 MiB | 单帧或分片累计超限 → close `1009` |
| `SOCKET_READ_TIMEOUT_MS` | 60 000 | **实际生效的空闲断连**：60 秒收不到任何字节就关 |
| 心跳 | 每 10 秒 | 服务端主动发 WS `PING`（空负载） |
| `IDLE_TIMEOUT_MS` | 150 000 | 心跳任务里的空闲检查；因为 60 秒读超时先触发，这条基本不会命中 |

握手细节：非 `GET` → `405`；缺 `Sec-WebSocket-Key` → `400`；
两者都带中文正文 `spw-remote：这里是 WebSocket 端点，请用 WebSocket 协议连接`。
客户端发来的帧**必须带掩码**，否则 close `1002 "client frame must be masked"`；
未支持的 opcode → close `1002`。

> **客户端要自己实现重连。** 服务端每 10 秒发一个 PING，任何入站帧都会刷新空闲计时器，
> 但只要 60 秒完全没数据就会被断开。建议客户端每 30 秒发一条应用层 `ping`。

## 二、客户端 → 插件

| `t` | 字段 | 类型 | 说明 |
| --- | --- | --- | --- |
| `auth` | `token` | string | 配对。非字符串按空串处理。**必须是第一条** |
| `hello` | — | — | 握手，回 `hello` + `state`（需要已配对） |
| `ping` | `ts` | number \| string \| 缺省 | 应用层心跳，回 `pong`。**未配对也放行** |
| `netinfo` | — | — | 要地址列表。别名：`addrs` |
| `cmd` | `id` | 任意 JSON 值 | 指令 ID，回执时**原样回传** |
| | `action` | string | `play` \| `pause` \| `next` \| `prev` \| `seek`，必填 |
| | `pos` | number \| string | 仅 `seek` 需要，单位毫秒，必须 ≥ 0 |

`id` 和 `pos` 允许写成数字或数字字符串（`asLongOrNull` 两种都吃）。

### `cmd` 的完整动作表

| action | 调用 | 备注 |
| --- | --- | --- |
| `play` | `WorkshopApi.playback.play()` | |
| `pause` | `WorkshopApi.playback.pause()` | |
| `next` | `WorkshopApi.playback.next()` | |
| `prev` | `WorkshopApi.playback.previous()` | 注意协议名是 `prev`，API 名是 `previous` |
| `seek` | `WorkshopApi.playback.seekTo(pos)` | `pos` 缺失或为负 → 直接报错，不调用 |

### `ack` 的错误串（`err` 字段）

按出现顺序：

| 错误串 | 触发条件 |
| --- | --- |
| `缺少 action 字段` | `action` 缺失或空白 |
| `未知 action: <action>` | 不是上面 5 个 |
| `seek 需要非负的 pos 参数（毫秒）` | `seek` 但 `pos` 缺失/为负 |
| `<宿主抛出的异常 message>` | 宿主 API 调用抛异常 |
| `<3 秒超时的异常 message>` | 指令超过 3 秒没返回 |

## 三、插件 → 客户端

### `authRequired` — 需要配对

`onOpen` 立即发送；未配对时收到任何被挡下的消息也会再发一次。

```json
{"t":"authRequired","protocol":1}
```

### `authOk` / `authFail`

```json
{"t":"authOk"}
{"t":"authFail","err":"配对码不对"}
```

`authFail` 目前只有「配对码不对」一种原因。配对成功时按
`authOk` → `hello` → `state` 的顺序连发三条。

### `hello` — 握手应答

```json
{"t":"hello","ok":true,"protocol":1,
 "app":"Salt Player for Windows (SPW Remote)","version":"1.0"}
```

`version` 是**插件版本**。注意 `app` 是固定字符串，不是宿主的真实名称，
`hello` 里**没有插件 ID**（插件 ID 只在 UDP beacon 的 `plugin` 字段里）。

### `state` — 播放状态

**11 个键恒定存在**，缺失值用空串 / `0` / `false` 表达，不会出现 JSON `null`。

```json
{"t":"state",
 "playing":true,
 "title":"曲名","artist":"艺术家","album":"专辑","albumArtist":"专辑艺术家",
 "path":"C:\\Music\\x.flac",
 "pos":12345,
 "id":"",
 "lyric":"",
 "ts":1730000000000}
```

| 字段 | 类型 | 可靠性 |
| --- | --- | --- |
| `playing` | bool | 官方事件 + 反射对账 |
| `title` `artist` `album` `albumArtist` `path` | string | **官方接口，稳定** |
| `pos` | number | 毫秒。事件 + 反射对账 |
| `id` | string | **尽力而为**：反射读宿主内部字段，拿不到是空串。**不要当主键依赖** |
| `lyric` | string | ⚠️ **当前恒为空串**，见下 |
| `ts` | number | 服务端发出时的 `System.currentTimeMillis()` |

> ⚠️ **`lyric` 目前恒为空串。**
> `MediaState.onLyricLine()` 已经写好了，但 `RemotePlaybackExtension` 没有覆写
> `onLyricsLineUpdated`，所以**没有任何调用者**，`snapshot.lyricLine` 只在换曲时被置空。
> 客户端不要依赖这个字段，等宿主升级到提供 `onLyricsLinesUpdated` 之后再启用。

`state` 里**没有** `duration`、没有封面、没有任何 `null` 字段。

### `netinfo` — 网络地址（需已配对）

```json
{"t":"netinfo",
 "name":"Salt Player for Windows",
 "wsPort":52100,
 "udpPort":52101,
 "lan":["192.168.0.106"],
 "ipv6":["240e:...:1"],
 "public":"123.161.182.63",
 "token":"SPW-7K2M9QX4",
 "trackReflector":"可用，命中字段 currentMediaItem"}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `wsPort` / `udpPort` | number | 当前实际端口 |
| `lan` | string[] | 局域网 IPv4。**只含 10/8、172.16/12、192.168/16**，`100.x`（Tailscale/CGNAT）不算 site-local，不会出现在这里 |
| `ipv6` | string[] | 全局 IPv6，已过滤回环 / 链路本地 / 唯一本地（`fc00::/7`）/ 组播 |
| `public` | string \| **null** | 公网 IPv4。探测失败是 `null` |
| `token` | string \| **null** | 「局域网免配对」开启时给配对码，关闭时是 `null` |
| `trackReflector` | string | 诊断串：`可用，命中字段 <字段名>` 或 `不可用：<原因>` |

### `error`

```json
{"t":"error","err":"未知消息类型: echo"}
```

可能的值：`消息不是合法的 JSON 对象`、`缺少 t 字段`、`未知消息类型: <t>`。

### `pong`

```json
{"t":"pong","ts":123}
```

`ts` **键总是存在**，但如果请求里没带 `ts`，值就是 JSON `null`。

### `ack`

```json
{"t":"ack","id":1,"ok":true}
{"t":"ack","id":1,"ok":false,"err":"缺少 action 字段"}
```

`id` 原样回传（请求里没有就是 `null`）。
**成功时 `err` 键被整体省略**，不是 `null` —— 客户端判断成功用 `ok`。

## 四、状态推送时机

| 触发 | 强制? | 发给谁 |
| --- | --- | --- |
| 配对成功 | 定向 | 该连接 |
| 收到 `hello`（已配对） | 定向 | 该连接 |
| 换曲（歌词回调带来新的 `MediaItem`） | 内容变化时强制 | **所有连接** |
| 周期对账发现内容变化 | 强制 | **所有连接** |
| 播放/暂停切换 | 强制 | **所有连接** |
| 播放状态变 Idle/Ended | 强制 | **所有连接** |
| 位置更新（宿主每秒一次） | 否，受节流 | **所有连接** |
| 遥控指令成功后 | 强制 | **所有连接** |
| 周期对账（首次延迟 3 秒，之后每 4 秒） | 只在内容真的变了时 | **所有连接** |

节流：非强制广播的最小间隔 **900ms**。
所有广播都排到单线程调度器上串行发出。

> ⚠️ **广播不做配对过滤**：`WsServer.broadcast()` 会遍历全部已建立的连接。
> 所以未配对的连接虽然在 `onOpen` 那一刻收不到东西，但**下一次状态广播就会收到 `state`**。
> 也就是说 `playing/title/artist/path` 对同网段任何连上端口的程序都是可读的。
> 详见 README「安全模型」。

## 五、UDP 自动发现（端口 52101）

### 广播包（beacon）

插件每 **5 秒**向每个网卡的定向广播地址（`x.y.z.255`）和 `255.255.255.255`
发一份 JSON。**共 8 个键，且不含任何地址字段**：

```json
{"t":"spw-remote",
 "name":"Salt Player for Windows",
 "plugin":"io.github.motian16.spwremote",
 "version":"1.0",
 "wsPort":52100,
 "udpPort":52101,
 "auth":true,
 "token":"SPW-7K2M9QX4"}
```

| 字段 | 说明 |
| --- | --- |
| `t` | 恒为 `"spw-remote"`，客户端据此识别 |
| `plugin` | 插件 ID（`pluginContext.pluginId`） |
| `auth` | 恒 `true`，提示客户端"需要配对" |
| `token` | 「局域网免配对」**开启时是配对码字符串，关闭时是 JSON `null`**（键仍存在） |

> 广播没有 `lan` / `ipv6` / `public` / `eps` 字段。地址列表只在配对成功后
> 通过 WebSocket 的 `netinfo` 下发 —— 广播会被同网段所有人看到，不带地址是有意的。

### 主动探测（让发现快一个 RTT）

客户端往同一个 UDP 端口发一条**包含子串 `"probe"`**（注意带双引号）的报文，
插件会**立即向来源地址单播回一份同样的 beacon**：

```json
{"t":"probe"}
```

这样客户端一进控制页最多等一个 RTT，不用赌 5 秒广播的相位。
探测**没有鉴权也没有速率限制**，任何能发包的程序都会得到回复。

| 常量 | 值 | 出处 |
| --- | --- | --- |
| 广播间隔 | 5 000 ms | `Discovery.kt` `BROADCAST_INTERVAL_MS` |
| 收包缓冲 | 4 KiB | `Discovery.kt` `MAX_PACKET` |
| 探测识别 | 文本包含 `"probe"` | `Discovery.kt` `ProbeCode` |
| 绑定 | `0.0.0.0:52101`，`reuseAddress` + `broadcast` | `DiscoveryService.start()` |

> `Discovery.kt` 里的 `ReplyCode`（`"reply"`）是**预留常量，当前未被使用**；
> 只有 `DiscoverySelfTest` 的测试 payload 里会出现 `eps` 数组 —— 那**不是**真实插件的格式。

## 六、公网 IPv4 探测

按顺序尝试，第一个成功即用（`Discovery.kt` 的 `DEFAULT_ENDPOINTS`）：

1. `https://api.ipify.org/`
2. `https://ifconfig.me/ip`
3. `https://ipv4.icanhazip.com/`

| 项 | 值 |
| --- | --- |
| 结果校验 | `^\d{1,3}(\.\d{1,3}){3}$` |
| 缓存 | 10 分钟；`force` 可绕过 |
| 全部失败 | **返回上一次缓存值**（不更新缓存时间） |
| 连接 / 读取超时 | 各 4 000 ms |
| 传输 | 手写 HTTP/1.1 over 原始 TLS socket（宿主没有 `java.net.http`） |
| 证书校验 | **接受任意证书**（只用于「问我的出口 IP」，不参与任何安全决策） |

可以用配置页的 `remote.publicIpProbe` 整个关掉。

## 七、自测入口

三个 `main()`，都不依赖宿主，用来单独验证各部分：

```powershell
# 假宿主 + 真插件：验证配对流程、WebSocket、反射降级行为
java -cp <classes> io.github.motian16.spwremote.PluginSelfTest [wsPort=52300] [udpPort=52301] [秒数=40]

# 只用 java.base 的 WS 服务端：验证线协议（配合 test-client/verify-ws.js）
java -cp <classes> io.github.motian16.spwremote.WsServerSelfTest [port=52199]   # 固定跑 60 秒

# UDP 广播与地址探测
java -cp <classes> io.github.motian16.spwremote.DiscoverySelfTest [wsPort=52100] [udpPort=52101] [秒数=30]
```

`PluginSelfTest` 用的假配置是 `remote.token = "test-token-42"`，
所以配合 `test-client/verify-auth.js <host> <port> test-token-42` 可以直接验证配对流程。
注意 `WsServerSelfTest` **没有鉴权**，它只用来验证 WebSocket 实现本身。
